# Reader 多版本存档导出架构与 1.20.1 适配测试计划

日期：2026-11-24。状态：以下保留最初架构计划；首轮代码适配与合成数据测试已完成，
真实原生 1.20.1 存档验收尚未完成。实际落地范围及未完成项见
[适配进展](native-world-export-1.20.1-progress.md)，不能将整份计划视为已实现。

## 1. 本轮目标与边界

优先打通 Minecraft 1.20.1 存档 → LT 几何／材质 → OBJ 的可复现链路，同时保留 1.12.2 回归。维持 Python App／生成端与 C++ 核心的分工，不开始 Flutter 重写，不把服务器帮助／反馈重接入混入本轮。

用户明确的支持边界：只接受目标 Minecraft＋加载器＋对应 LT／模组环境原生创建和保存的存档。升级、降级或跨版本迁移过的存档不在支持与验收范围内；不能通过升级 1.12.2 存档制作 1.20.1 验收样本。Reader 不执行存档升级、修复或迁移恢复。仅凭元数据无法证明存档从未升级，样本必须保留来源记录；已知迁移或识别到格式冲突时应提示不受支持。

版本支持按能力分别记录：存档识别、普通方块读取、LT 几何读取、状态／材质、普通方块模型还原、桌面调用。不能以“能写出 OBJ”代替完整支持。

普通方块当前采用完整立方体近似。本轮先验收 LT 与普通完整方块；台阶、楼梯、植物、流体、连接模型、方块实体渲染等列为独立能力，不把它们的立方体近似写成已还原原貌。

## 2. 现有基础与已核实问题

| 位置／符号 | 当前情况 | 风险／处理方向 |
| --- | --- | --- |
| `ChunkBlocks::ReadIds12` / `ReadNames118` | 已分旧数字 ID 与现代 palette 两条路径 | 可以复用；不需要重写全部存档解析 |
| `ChunkTileEntities` / `BlockTileEntities` | 已有两代 LT 存档数据处理和新版扩展盒子支持 | 固定实际 LT 构建验证；不能只依据 MC 版本猜 LT 数据布局 |
| `ChunkBlocks::ReadNames118` | palette 只读取 `Name`，没有保存 `Properties` | 同名不同轴向／朝向合并，后面无法正确选材质／模型 |
| `ChunkBlocks` / `CgalWorldBlocks` | 紧凑的 16 位索引；区域重建也按名字合并 | 改成完整状态的索引；必须有容量检查，不允许溢出回绕 |
| `ChunkBlocks::ReadNames118` | 高度固定为 -64..319；缺失 data 时填首项 | 维度高度与存储格式解耦；多项 palette 缺 data 应报错 |
| `CgalWorldBlocks` | 采用首个区块布局／高度作为区域依据 | 不能把混合版本区块或空首区块一概按同一种布局处理 |
| `CgalWorldBlocks` | 普通非空气邻居通常视为遮挡 | 透明与非完整方块可能误删可见面；不能仅由非空气推断遮挡 |
| `main.cpp` | 普通方块导出仍统一尝试旧 `block_ids.tsv`，现代输入也可能收到缺表警告 | 只对数字 ID 解码器要求映射表 |
| `tools/resolve_block_textures.py` | 旧 metadata family、首个 variant、每方向第一层；父模型处理会去掉命名空间 | 现代属性、多层、跨命名空间继承和旋转不可靠 |
| `app/vanilla.py` | 文案和补全纹理逻辑仍按 1.12.2；复制 `textures/blocks` 和固定 ID 表 | 现代 `textures/block` 应按资源位置解析；现代流程不依赖旧 ID 表 |
| `BlockTextureTable::Lookup` | 跨代名称兜底可使新版存档配旧素材显示 | 应成为显式兼容选项，不能代替原生 1.20.1 素材验收 |
| `Library.Source` / `Project` | 没有完整的 MC／LT 环境约束 | 两代素材、模组和项目可能误混 |
| `compose.order_fingerprint` | 当前仅散列有序启用 ID | 缺生成器／契约／目标版本信息，代码升级后可能复用旧缓存 |

`docs/known-issues.md` 已记录过同建筑 1.12.2／1.20.1 的对照结果，说明新版存档读取并非从零开始。但该历史记录主要用了旧素材兼容兜底，不作为本轮“原生 1.20.1 材质与全部状态已验收”的证据。

### 2.1 必须保留的整体 Structure 读取修复

工作区已有尚未提交的修复：`BlockTileEntities::ReadTileCollectionNbt` 不再只读取 `content.tiles`，还递归读取 `content.children[*].tiles`。这覆盖存档中归属于整体 Structure 的本地小方块集合；读取出来的仍是实际盒子几何，不迁移整体破坏、交互或动画行为。

同时保留：父／子集合中重复材质组追加盒子而不是丢弃；颜色与独立 meta；子集合参与 LT host 覆盖判定；错误子项不丢弃有效兄弟几何。

旧版结构中的 `coord`、`structure.blocks` 是关联信息，不应重复作为几何平移或追加盒子。新版此类关联的完整语义必须依据目标 LT 构建单独核对，不能从旧版直接推广。

2026-11-24 已重新运行当前构建的 `block_tile_entities_test`，通过。该测试覆盖旧版／现代合成 NBT、子集合、重复材质、颜色、偏移与关联字段处理；尚不等于目标 1.20.1 原生真实整体结构已通过游戏对照验收。P0 应专门准备“普通散放 tiles”和“整体 Structure”两组实物样本，并包含跨方块／跨区块的结构。

## 3. 架构：统一输出，按格式家族适配

保留主链路：

`探测环境 → 选择输入适配器 → 解码为统一方块状态和 LT 盒子 → 绑定准备好的素材 → 共用几何／UV／导出器`

不要每个 MC 小版本复制一套 Reader，也不要把所有判断继续加到 `main.cpp`。先用少量明确模块与注册表实现，暂不引入动态插件系统。

### 3.1 输入环境与兼容配置

建议增加 `WorldProbe` 与 `CompatibilityProfile`：

- 探测 `level.dat` 的版本信息，逐区块读取 `DataVersion`；元数据缺失时结合字段形状标记“推断”，不伪造精确版本。
- 明确 MC 版本、区块存储家族、LT 存储家族、维度、素材环境及探测依据。
- 先注册 1.12.2 与 1.20.1 两套已测试配置；共享同一存储规则的未来版本可复用解码器，但只有完成验收才列入支持矩阵。
- 检查世界与区块的版本／布局是否符合所选原生环境；已知升级／降级、跨版本迁移或布局冲突不进入支持流程。不为此引入混合版本恢复功能，也不声称元数据相同就能证明从未升级。
- 主世界／下界／末地分开验证高度与路径；自定义维度先探测并明确能力范围，不能把主世界高度当成所有现代维度的默认事实。
- 新增 `--inspect-world` 或等价只读探测接口，返回结构化证据与警告，供 App 和测试工具共用。

MC 版本、LT 版本、Reader 版本、素材契约版本分别存储，不能由单个 `version` 字段代替。

### 3.2 方块标识与状态

运行期统一表示为“命名空间 ID ＋ 属性集合”，例如：

```text
minecraft:oak_log[axis=x]
minecraft:oak_log[axis=y]
```

属性键排序生成稳定 key；保存原始来源用于诊断。每个空间位置只存 intern 后的整数索引，属性字符串共享，避免给几百万个方块各放一份 map。

- 1.20.1：palette 中的 `Name` 与 `Properties` 直接归一化，不经过 1.12 ID 表。
- 1.12.2：数字 ID＋meta 通过旧版注册表适配器解释。原版固定表与模组注册表分开；模组数字 ID 不能假定跨存档固定，没有可靠映射则保留 unknown 并报告。
- LT 材质里的旧字符串、分离 meta 或现代属性字符串，也在输入边界归一化。
- `BlockStateMap` 保留给显式跨代转换／旧素材兼容用途；原生 1.20.1 导出不强制转换回 1.12 名字。
- 空气判定包括 air／cave_air／void_air，不能把状态索引非零等同于实心／遮挡。
- 首轮可保留现有紧凑存储，增加上限检查；如统一改为 32 位状态索引，需要同步测大选区峰值内存，不能把每格扩为复杂对象。

### 3.3 区块与 LT 解码适配器

最初只需明确旧数字布局与现代 palette 布局两类入口，把格式选择从业务流程中抽离。MC 与 LT 分开分派，共用已有 NBT、盒子解码、坐标换算与裁剪。

必须覆盖：单项 palette 无 data、多项 palette 位宽、long 尾部填充、负 Y、负区块坐标、Add／meta、错误长度、非法 palette 索引，以及 LT host 去重／覆盖面。

当前 Anvil 只接受压缩类型 2。先记录目标样本实际使用的压缩与外置区块情况；不支持的类型应明确失败，不能当空区块成功。更广的压缩或 `.mcc` 支持按实际样本与支持承诺安排。

### 3.4 素材生成与版本隔离

继续让 Python 解包 JAR、解析 blockstates／models、组合资源；C++ 只读取已准备的素材契约。

1. 原版客户端 JAR 记录实际版本与内容哈希；LT JAR 记录模组标识、版本、加载器及声明兼容范围。
2. 素材环境绑定一份原版底包、对应 LT 模组，以及有序的可选资源包。1.12.2 和 1.20.1 各有独立环境，资源文件可按哈希共享，但启用配置和组合缓存不能共用。
3. 资源位置始终为 namespace＋path；按文件真实位置解析 `textures/block`／`textures/blocks`，不再全局做字符串替换。
4. 父模型继承和 `#texture` 引用保留命名空间；检测循环、缺失依赖与未支持的动态加载器。
5. 现代 blockstate 按实际属性匹配 variants／multipart，处理模型 x/y 旋转、uvlock 和逐面 UV。不能选择 JSON 第一项当作所有状态的外观。多个带权候选采用可复现的选择策略，并在测试记录中固定。
6. `pack_format` 作为兼容提示之一，不作为唯一 MC 版本识别依据；未知版本或跨版包由明确的兼容模式处理，默认原生验收不混用。

素材契约演进分两步：先补强 manifest 的 MC／LT／来源／生成器信息和校验；再新增版本化的“完整 state key → 已解析材质／模型”表。面数据需能携带贴图、UV、旋转、tint 与渲染／遮挡信息；单纯六面贴图 TSV 无法承载任意多层和非立方体模型。

不一次性枚举所有模组状态。可利用只读扫描得到实际出现的 state 集合，再按需编译素材并缓存；首次允许多读一次选区，后续再依据性能数据优化。扫描与导出间输入变化须失效重扫。

旧 TSV 契约仍能供旧核心消费；新能力通过明确的契约版本和核心 capabilities 协商，避免旧核心忽略字段后输出近似结果却显示成功。

建议缓存指纹包含：MC profile、原版 JAR 哈希、LT／其他模组哈希、有序资源包哈希、素材契约版本、生成器版本及解析模式。使用新缓存目录并校验完成后切换，防止构建失败留下可复用的半成品。

### 3.5 App 中的版本切换

不只加“版本”下拉框，而是让每个项目绑定一个“游戏环境”：

```text
环境 A：MC 1.12.2 ＋ 对应原版素材 ＋ 对应 LT 构建 ＋ 可选资源包
环境 B：MC 1.20.1 ＋ 对应原版素材 ＋ 对应 LT 构建 ＋ 可选资源包
```

- 选存档后显示探测结果，默认自动选择匹配环境。
- 用户切换的是素材／兼容环境，不会转换、升级或改写存档。
- 手动覆盖只开放已知兼容范围，记录覆盖原因；明显不匹配不静默继续。
- 旧项目暂归为 legacy／待确认，不自动把旧素材标为 1.20.1。
- job、导出记录、重导出与 ZIP 清单记录环境指纹、核心能力、各 chunk 数据版本分布、近似／缺失统计。
- 不把环境定义写死到 Qt 控件中，保存在独立数据层，便于将来 Flutter 复用。

## 4. 实施顺序和验收门槛

### P0：固定 1.20.1 基线，先测后改

收集并记录一套真实客户端、加载器、LT 构建、原生 1.20.1 测试存档与素材；测试只用副本，保留原生创建来源记录。对现有核心运行选区导出，保存 job、日志、计数、包围盒和缺失材质清单，形成现状报告。同时固定独立原生创建的 1.12.2 回归样本；禁止拿升级／迁移存档充当新版验收样本。

产出：支持矩阵、已复现问题、每个问题的最小样本。历史测试数据只能作参考，不能把旧记录当作本轮结果。

### P1：环境探测、方块状态和解码正确性

先保留并回归整体 Structure 子集合修复，再修 palette 丢属性、空气判定、错误数据静默填充、索引容量、现代路径不应要求旧 ID 表等问题；加入版本探测和按格式家族组织的解码入口，验证 LT 几何与层级 grid。不同版本的适配器服务各自原生存档，不承担迁移恢复。

门槛：与游戏／参考解析数据逐项对照位置、名称、属性、盒子、颜色；不存在“不同朝向被合并为一种状态”。

### P2：原生 1.20.1 素材链路

建立该版本原版＋对应 LT 素材；修复命名空间、路径、父模型、属性选材质与面方向；补素材契约与缓存环境信息。以完整方块的不同朝向和 LT 贴图为先，透明／多层／非立方体逐项标注能力。

门槛：原生样本不依赖 1.12 名称兜底；指定必测素材无缺图、错图或 UV 镜像。对支持范围外的模型给出可定位报告。

### P3：现有 App 接入环境

先用 job／测试脚本稳定 P1、P2，再修改项目配置、素材库与当前导出界面。验收自动识别、手动覆盖、错配拦截、切换缓存和历史重导出；不在此阶段重写界面。

### P4：真实存档与回归验收

小样本逐项核对，中样本检验复杂组合，大样本测时间与峰值内存。1.12.2、1.20.1 使用各自原生素材分别验收。只有通过的能力写“已测试”，未通过项目保留限制。

## 5. 必测矩阵

| 类别 | 场景与检查 |
| --- | --- |
| 版本识别 | 各自原生创建的 1.12.2／1.20.1、缺 level.dat、缺 DataVersion、版本／布局冲突、未知新数据版本；已知升级／迁移样本仅验证拒绝或提示，不作为导出支持验收 |
| 普通状态 | 石头、不同颜色方块、原木 axis=x/y/z、带 facing 的完整方块；检查状态与贴图方向 |
| palette | 单项无 data；跨不同位宽、long 边界；越界索引、损坏／缺失 data 必须报告 |
| 空间 | 负 X/Z、跨区块／region、负 Y、高度边界、主世界／下界／末地 |
| LT 几何 | 普通散放 tiles 与整体 Structure 分别覆盖；普通盒子、偏移／裁剪、子层 grid、颜色、父子同材质、跨方块／跨区块结构；OBJ 路径不套用 BB 的斜面限制 |
| LT host | 普通方块不重复导出 LT 容器；部分覆盖不误删邻面；跨区块覆盖一致 |
| 素材 | 原版 1.20.1 新方块、对应 LT 方块、多 namespace 继承、缺图、循环引用、资源包覆盖顺序 |
| 外观边界 | 玻璃／树叶、tint、多层、楼梯／台阶／植物；明确哪些准确还原、哪些近似或不支持 |
| 输出 | OBJ／MTL／PNG 引用完整；缺材质不沿用上一块材质；可移机解压检查 |
| 应用 | 环境切换、错配、取消、项目搬迁、旧配置升级、重导出可复现、不同版本缓存不串用 |
| 性能 | 小／中／大选区的耗时和峰值内存，含状态表容量与按需素材编译成本 |
