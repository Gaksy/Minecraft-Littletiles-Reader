存档从创建起是否原生使用该环境仍未核实，实际视觉效果亦待用户确认；这不等同于最终原生存档验收。

## 版本与存档

- 首批配置为 1.12.2（DataVersion 1343）和 1.20.1（3465）。显式选择与数据冲突时拒绝导出。
- 缺失 DataVersion 时只能按区块字段布局推断并警告，不能据此确认精确版本或创建历史。
- 仅支持从创建起使用目标版本及对应模组环境的存档。不支持升级、降级、跨版本迁移；读取不会升级或修改存档。
- 现代区块保留完整命名空间方块状态及属性，严格检查调色板索引和打包数组；高度来自实际存储的 section 范围。
- 保留此前 LT Structure 的父级和 `content.children` 内 tiles 收集修复。同材质盒子追加，颜色保留；不把结构连接元数据当作几何变换。

## 素材与模型边界

素材生成在 App／Python 端完成，C++ 消费归一化表。现代素材绑定 Minecraft 版本与生成器修订，不能用旧版 ID／材质表静默代替。
资源保留命名空间；解析 JSON 父模型、纹理引用、variant、方块状态旋转、面 UV 与 uvlock。
多候选 variant 固定选择首项并记录，便于复现，不模拟游戏中的随机分布。

本阶段仅支持单个完整 0..16 立方体及其六面资源定义。部分立方体、多部件、multipart、自定义 loader、动态渲染等写入
`unsupported_states.json`。资源包严格版本检查目前覆盖现代格式，不能理解为兼容任意版本资源包。

LittleTiles 几何和材质是独立的概念：读取 LT 盒子不等于具备其它模组的模型渲染器。
LT 使用的模组材质也需要可解析的资源映射；任意模组的普通模型方块不属于已支持范围。
OBJ 对缺失映射给出警告和缺失面统计，不保证保留该方块的实际形状或外观；BB 首版仍遵循标准长方体限制。

### 已实现的素材格式 v2

`manifest.json` 设置 `format_version: 2`、`minecraft_version: "1.20.1"`，并记录数据版本、生成器修订与源资源指纹。
`block_textures.tsv` 每行 49 列：完整方块状态、六面纹理、六面 tintindex、六组各六项的 UV 仿射参数。
面顺序沿用原表契约。每面 `(a,b,c,d,e,f)` 将 `(u,v)` 映射到 `(au+bv+c,du+ev+f)`。
纹理引用保留命名空间目录。旧版素材 v1 继续用于旧流程；现代存档带素材导出要求版本匹配的 v2。

## 使用与验证

App 的导出对话框可选择自动识别／1.12.2／1.20.1，并保存选择；素材源通过现有素材库管理。
这还不是自动管理游戏、加载器、模组依赖与存档来源的完整环境管理器。
Job 参数见 [job.md](job.md)，核心能力探测使用 `--capabilities`。

验证命令：

```text
ctest --test-dir build-release --output-on-failure
python tests/test_native_1201.py
python tests/test_bbmodel.py
```

后两项在 App 仓库执行。原生适配测试使用程序生成的资源和 MCA 数据，覆盖状态属性、旋转 UV、负坐标、缺失首区块、
LT 子结构、版本冲突与损坏数据；不代表真实游戏创建的原生存档验收。既有 App 导出配置、坐标、素材源、材质、项目、打包、粘贴与翻译检查也已回归。

后续验收需要原生 1.20.1 实例、准确的 LT／加载器／模组版本，以及覆盖普通方块、LT Structure 和边界高度的原生存档。
level.dat 全存档预检、完整环境切换、复杂模型渲染仍是后续工作。
