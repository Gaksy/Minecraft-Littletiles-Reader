# 动画贴图的静态帧导出

2026-11-24：已实现、构建并通过自动测试；未替换安装版，未正式发行。

海晶灯的原版 1.20.1 PNG 为 16×80，包含 5 个 16×16 动画帧。原流程丢弃了 `.png.mcmeta`，
将整条帧图作为一张贴图映射到方块面，导致外观看起来被拉伸。这不是模型尺寸或 UV 比例的问题。

按用户要求，所有带动画定义的纹理统一输出动画序列第一帧，OBJ 和 BB 共用同一规则：

- 读取 PNG 同级的 `<name>.png.mcmeta`，有 `animation` 时按帧尺寸裁切，不缩放整条图。
- 缺省帧尺寸为较短边形成的正方形；显式 width／height 按动画元数据解释。
- 有 frames 序列时取首项的 index，支持数字和 `{index,time}` 两种写法；无序列或空序列时取索引 0。
- 支持纵向、横向以及多行帧网格。选帧后再执行 tint 和 LT 颜色调制。
- 无动画元数据的长方形纹理保持原样，不仅凭长宽比猜测动画。
- 错误的元数据、不可整除的帧尺寸或越界首帧明确失败，不输出被压缩的整条帧图。
- 这是静态快照，不保留播放、帧时长或插值。BB 仍要求选出的帧为正方形。

App 素材生成与资源覆盖流程保留 `.png.mcmeta`，现代素材指纹计入该元数据；生成器修订已更新，
避免旧缓存继续忽略动画。高优先级静态 PNG 覆盖动画 PNG 时同时移除旧 sidecar。
以前生成且已丢失 sidecar 的素材需要重新生成，不能靠核心猜测修复。

核心 `texture_animation_test` 验证像素裁切、序列、横纵帧、错误元数据、染色及无染色输出、BB 内嵌；
App `tests/test_texture_animation.py` 验证元数据复制、缓存指纹、覆盖与真实 OBJ／BB 调用。
对应 1.20.1 实测导出已重新生成；海晶灯输出为 16×16，几何和 UV 与上一份逐字节一致。
